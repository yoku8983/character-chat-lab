# 設計書: 評価 GUI(ローカル専用)+ usage ダッシュボード強化

- 日付: 2026-07-04
- 関連: Issue #34(評価基盤の運用性改善)、Issue #20 T1(usage 実測ログ基盤)
- ステータス: ユーザー承認済み(ブレインストーミングセッションで合意)

## 背景と目的

- 評価ハーネス(`npm run eval` / `eval:quiz`)は CLI 実行のみで、パラメータ指定が煩雑。ブラウザ GUI から実行・結果閲覧したい
- `/usage` ページは URL 直打ちでしか到達できず、集計も日別・モデル別のみ。日次/月次の消費量と円換算コストを画面遷移で見たい

## 要件(ユーザー確定事項)

1. **評価 GUI はローカル開発環境限定**。本番(Azure)では一切露出しない。usage 強化は本番でも表示する
2. GUI の機能範囲: **実行 + 結果表示 + 履歴一覧**(compare の GUI 化はスコープ外)
3. 円換算は**固定レート(環境変数 `USD_JPY_RATE`、既定 155)**。為替 API は使わない
4. 実現方式: **案A = 本体 Next.js アプリに同居**し、ローカル専用ガードで隔離(スタンドアロン別ツールにはしない)

## 設計 1: 評価 GUI(`/eval`)

### ローカル専用ガード

- 環境変数 **`EVAL_UI_ENABLED=1`** を `.env.local` に記述したときのみ有効。本番 Azure には設定しない
- `/eval` ページと `app/api/eval/*` の全 route は、この変数が無ければ **404** を返す
- `NODE_ENV` 分岐ではなく明示的な opt-in とする(「本番でうっかり有効」を構造的に防ぐ)

### 画面構成(`app/eval/page.tsx`、1ページ・3ブロック)

1. **実行フォーム**
   - 評価種別: multi-turn 評価(eval) / 知識クイズ(quiz)
   - ペルソナ: DB 登録済み一覧から選択、またはローカルファイルパス直接入力(`--persona-file` 相当)
   - データセット: パス入力(eval では任意=参照付き Judge、quiz では必須)
   - モデル・temperature・シナリオ数・max-turns
   - 実行前に**推定 API コール数とコスト目安**を表示(`sweep.ts` の既存見積りロジックを流用)
2. **実行中パネル**: 進捗(シナリオ n/m・現在ターン)を 2 秒間隔のポーリングで表示。中断ボタン付き
3. **履歴一覧**: `eval/reports/*.json` をサーバーで列挙。日時・ペルソナ・モデル・judge 平均・refFidelity・正答率(quiz)・コストのテーブル。行クリックで詳細(シナリオ別テーブル = CLI `printSummary` 相当)を展開

### API(すべて `EVAL_UI_ENABLED` ガード付き)

| Route | 役割 |
| --- | --- |
| `POST /api/eval/run` | ジョブ開始。`runEval()` / quiz 実行ロジックを同一プロセスで直接 import して非同期実行。**同時実行は 1 ジョブまで**(実行中は 409) |
| `GET /api/eval/status` | 実行中ジョブの進捗(メモリ上のジョブオブジェクト) |
| `POST /api/eval/cancel` | 中断フラグを立てる(次のシナリオ境界で停止) |
| `GET /api/eval/reports` | レポート一覧(メタ情報のみ) |
| `GET /api/eval/reports/[filename]` | レポート詳細。**ファイル名のみ許可**(パストラバーサル対策: パス区切り文字を含む名前は拒否し、`eval/reports/` 配下のみ読む) |

### ハーネス側の小改修

- `runEval(cfg)` に `onProgress?: (info) => void` コールバックと中断シグナル(`shouldCancel?: () => boolean` 等)を追加。CLI からは未使用で挙動不変
- `quiz.ts` の実行ロジックを `quiz-runner.ts` 等の関数に切り出し、CLI と API で共用

### 既知の割り切り

- dev サーバーのホットリロードでメモリ上のジョブ状態が消え得る → 進捗表示が消えるだけで、レポート JSON はハーネスが最後まで書く(実害を局所化)
- データセットのパス入力はローカル FS に触れるが、ローカル専用ガード内なので許容

## 設計 2: usage ダッシュボード強化

### 集計の追加(`lib/db-usage-log.ts` `getUsageSummary` 拡張)

- **月次集計**を追加: `strftime('%Y-%m', created_at)` で GROUP BY(月・calls・トークン・cost)
- 全体サマリに「**今日**」「**今月**」の小計を追加

### 円換算

- 環境変数 `USD_JPY_RATE`(未設定時の既定値 155)。サーバー側(RSC)で換算し **$ と ¥ を併記**(例: `$0.0412 / ¥6.4`)
- `.env.example` に追記。目安表示であり厳密な為替ではない

### 画面(`app/usage/page.tsx` 改修)

- 上段: 今日 / 今月 / 累計 のサマリカード(¥ を主、$ を添える)
- 中段: 月別テーブル(新規)+ 日別テーブル(既存維持、直近 30 日に制限)
- 下段: モデル別テーブル(既存維持、cost に ¥ 併記)

### ナビゲーション導線

- `Header.tsx` に `<Link href="/usage">` で「利用状況」リンクを追加(本番でも表示)
- `/usage` に「← チャットに戻る」リンク +「評価」リンク(**`EVAL_UI_ENABLED` が有効なときのみ**。RSC で env を直接読み、クライアントに env を漏らさない)
- `/eval` にも同様の相互リンク

## エラーハンドリング

- 評価 API のエラー(データセット不正・`OPENROUTER_API_KEY` 未設定等)は日本語メッセージで画面表示
- ジョブ失敗はステータス `failed` + 理由を保持し、履歴/ステータス API から参照可能

## 検証方針

- 集計 SQL・円換算・レポートファイル名検証は tsx ワンオフで単体検証
- GUI は dev サーバーで実際に小規模評価(1 シナリオ × 2 ターン)を実行して e2e 確認
- `/usage` はローカル DB(`LIBSQL_URL` なし)で表示確認
- **`EVAL_UI_ENABLED` 未設定時に `/eval` と全 eval API が 404 を返すことを必ず確認**(セキュリティ上の要)

## スコープ外(申し送り)

- compare(Before/After 比較)の GUI 化
- 本番全 API が無認証である問題(**別 Issue として起票を推奨**。今回の設計はこれを悪化させない = 評価 GUI を本番に露出しない)
- 為替レートの自動取得
