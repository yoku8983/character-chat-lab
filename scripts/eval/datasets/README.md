# 正解データセット（参照付き Judge 用）

`scripts/eval/judge.ts` の参照付きモードで使う「正解応答例（原作準拠の模範応答）」を
JSON で定義するディレクトリです。`npm run eval -- --dataset <path>` で指定します。

## 著作権・隔離に関する注意（重要）

**原作のキャラクターの台詞・エピソードを含む実キャラ用データセットは、絶対にこのリポジトリに
コミットしないでください。** このディレクトリは `.gitignore` で以下のように隔離されています。

```
scripts/eval/datasets/*
!scripts/eval/datasets/README.md
!scripts/eval/datasets/example-*.json
```

- `README.md` とこのファイル名パターン `example-*.json`（架空サンプルキャラ専用）のみ追跡対象
- 実際に評価で使う本番キャラのデータセット（`*.json`）はこのディレクトリに置いてローカルでのみ
  使用し、コミットしないこと。必要であればリポジトリ外（別ディレクトリ）に置いても構いません

`example-tetsu-oyaji.json` は本リポジトリのサンプルペルソナ `personas/tetsu-oyaji.yaml`
（架空キャラ）専用のサンプルであり、実在の著作物からの引用ではありません。

## フォーマット

```jsonc
{
  "personaId": "tetsu-oyaji",
  "referencePairs": [
    {
      "situation": "状況・ユーザー発話",
      "reference": "この人物の本物の（原作準拠の）応答例",
      "canon": true, // true=原作の名場面由来 / false=原作にない状況
      "notes": "任意の補足メモ"
    }
  ]
}
```

- `personaId` / `referencePairs` は必須。`referencePairs` は1件以上必須
- 各ペアの `situation` / `reference` は空でない文字列、`canon` は真偽値が必須。`notes` は任意
- `knowledgeQuiz` は任意（後述）。それ以外の未知のフィールドは無視されます

## 知識クイズ `knowledgeQuiz`（ハルシネーション検出）

同じ JSON ファイルに `knowledgeQuiz` 配列を追加すると、`npm run eval:quiz` でキャラクター固有知識の
正誤・捏造（ハルシネーション）を機械判定できます。

```jsonc
{
  "personaId": "tetsu-oyaji",
  "referencePairs": [ /* 省略 */ ],
  "knowledgeQuiz": [
    {
      "question": "蒸気機関車は何を燃料にして走るんですか？",
      "mustContain": ["石炭"],
      "notes": "任意の補足メモ"
    },
    {
      "question": "あなたが機関士として走っていた、具体的な路線名を教えてください",
      "mustContain": [],
      "mustNotContain": ["函館本線", "宗谷本線", "石北本線"],
      "notes": "ペルソナ定義に具体的な路線名はない。架空の詳細をでっちあげていないかの検出用"
    }
  ]
}
```

### フィールド

- `question`（必須・空でない文字列）: ペルソナに単発のユーザー発話として投げる設問
- `mustContain`（必須・文字列配列。空配列可）: 正答条件。**配列内の全要素が応答に含まれていること（AND）**
  で正答とみなします。各要素自体は `"東京|とうきょう"` のように `|` で区切ることで表記ゆれを許容します
  （**候補のいずれか1つが含まれれば OK（OR）**）
- `mustNotContain`（任意・文字列配列）: ハルシネーション検出用。誤った固有名詞や捏造されがちな事実の
  キーワードを列挙します。**いずれか1つでも応答に含まれていたら不正解**にします
- `notes`（任意）: 補足メモ

### 採点の正規化

採点前に、応答・キーワード双方に対して「空白（全角スペース含む）を除去し、小文字化する」正規化のみ
行います。カタカナ⇄ひらがな変換などの意味的な正規化はしません（機械判定の予測可能性を優先するため）。

### 「知らないと答えるべき設問」の書き方

ペルソナ定義（YAML）に存在しない具体的な詳細（路線名・人名・日付など）をあえて尋ね、モデルがそれを
「知らない」と答えず**もっともらしい嘘を捏造していないか**を検出する設問です。この場合は
`mustContain: []`（空配列）にし、`mustNotContain` に「モデルが捏造しがちな具体的なキーワード」を
列挙してください。`mustContain` と `mustNotContain` の両方が空／欠落の場合は `loadDataset` がエラーで
弾きます（判定不能な設問を防ぐため）。

`mustNotContain` のキーワードは実行前に完全に予測しきれないことがあります。スモーク実行で捏造の
実例が見えたら、そのキーワードを追加して精度を上げてください。

## `canon: false` ペアを必ず含める理由（リファレンス過適合の防止）

参照付き Judge は「正解例の文言をそのまま使い回しているだけ」の応答を高評価にしてしまうリスクが
あります。これを防ぐため、データセットには **原作にそのまま存在する名場面（`canon: true`）だけでなく、
原作にない状況を想定した応答例（`canon: false`）を必ず含めてください**。`canon: false` のペアが
正しく評価できているかどうかは、「この人物らしさ」が原作の場面依存ではなく汎化して身についているかの
検証になります。目安として、全体の3〜4割程度は `canon: false` にすることを推奨します。
